A System-Agnostic Approach to Modelling Interaction Quality in Spoken
Dialogue Systems
Paul Gering ID 1, Roger K. Moore ID 1
1 School of Computer Science, University of Sheffield, United Kingdom
prgering1@sheffield.ac.uk, r.k.moore@sheffield.ac.uk
Abstract
Previous studies have used system-dependent (SD) input
features, such as system log data, and machine learning to
automatically evaluate user interactions with spoken dialogue
systems. However, this approach lacks generalisability across
different systems. This study implements a system-agnostic
(SA) approach, using acoustic, textual and temporal features to
model interaction quality (IQ). Across two experimental phases,
we compare the performance of IQ classifiers trained on static
and fine-tuned SD and SA features. We found that while the
SD features were superior in a static pipeline, the SA features
achieved comparable performance when end-to-end fine-tuning
was employed. Therefore, our results demonstrate that SA
features, when fine-tuned, offer a viable, system-independent
alternative for IQ modelling, enabling more scalable evaluations
across different dialogue systems.

1. Introduction
Evaluation is essential to the development of socially competent
and user-friendly spoken dialogue systems. Robust evaluation
facilitates the identification of specific interaction failures,
guiding system design to enable higher-quality user interactions.
To ensure efficiency and scalability, researchers have used
automatic metrics [ 1, 2], many of which have focused on
evaluating specific system components or individual responses
[3]. These metrics fail to capture the nuances of the interaction as
a whole, particularly the user’s role in shaping it. In contrast, this
study focuses on automating holistic, user-focused evaluations of
human-system interactions by training machine learning models
to predict interaction quality (IQ).
IQ was proposed by Schmitt et al. [ 4] as an objective
approximation of user satisfaction, which can be accurately rated
by expert annotators using observable dialogue behaviours. In a
series of studies, Schmitt et al. trained various machine-learning
models to classify IQ in conversations between a user and a
task-based dialogue system [ 4, 5, 6]. These classifiers were
trained on features automatically extracted from the system’s
log files, reflecting the internal status of various submodules.
This reliance on system-log data limits the generalisability of
the trained models, as the resulting IQ predictions are inherently
tied to a specific system architecture and task.
To improve the generalisability of IQ modelling, Gupta et
al. [7] proposed a system-agnostic approach, using textual and
temporal features to fine-tune a modified RoBERTa-base model
(RoBERTaIQ). This approach outperformed baseline models
that relied upon system metadata, demonstrating the viability of
using textual and temporal dialogue context for IQ classification.
However, this work was constrained by the absence of raw
acoustic signals in the dialogue data, preventing the researchers
from utilising paralinguistic features. Paralinguistic cues, such
as prosody and voice quality, convey vital information about the
user’s state, as evidenced by the frequent use of speech-based
features for emotion, engagement and error detection [8, 9, 10].
Therefore, we posit that integrating acoustic signals with textual
and temporal data provides a more holistic representation of an
exchange, enhancing IQ prediction.
To test this hypothesis, this study investigates whether a
system-agnostic (SA) feature set—composed of acoustic, textual
and temporal features—can outperform the system-dependent
(SD) feature set implemented by Schmitt et al. [ 4]. To
facilitate this comparison, we use the audio recordings and
system-log data from the CMU Let’s Go (LEGO) corpus. SA
features are extracted by transcribing the recordings and using
self-supervised models to derive high-level acoustic and textual
representations. Based on the architectural baselines established
in prior work [5, 6], we train long short-term memory (LSTM)
classifiers for multi-class IQ prediction. We further explore the
impact of end-to-end fine-tuning on classification performance.
By evaluating these approaches for IQ classification, this work
provides a critical step towards more robust and generalisable
methods of evaluating dialogue systems. The code for this
project is publicly available 1.
2. Method
2.1. LEGO Corpus
The LEGO corpus consists of telephone conversations between
a user and a bus information system [11]. Crucially, it is the only
publicly available spoken dialogue corpus with IQ annotations.
The first release (LEGOv1) consists of 347 dialogues, 237 of
which have corresponding audio recordings and exchange-level
IQ labels (1–5:extremely unsatisfiedtosatisfied). In this context,
an exchange is defined as a system prompt followed by a possible
user response.
After reviewing the 237 audio recordings, we excluded
eight dialogues where the user did not speak or spoke only to a
third party. We further excluded exchanges where the system’s
prompt was inaudible, as well as the first exchange of every
dialogue, as the system always produced the same introductory
prompts. Following these exclusions, the final dataset consisted
of 229 dialogues (5477 exchanges), which were partitioned at
the dialogue-level into training (80%) and test (20%) sets.
In line with the full corpus, the IQ labels within our subset
exhibit high inter-rater disagreement (mean agreement: Cohen’s

2.2. Feature Extraction and Processing
Two distinct feature sets were derived for this study: a baseline
system-dependent (SD) set and a system-agnostic (SA) set. The
SD set consists of features automatically extracted from the
system log files, as utilised by Schmitt et al. [4]. In contrast, the
SA set consists of acoustic and linguistic features extracted from
the interaction transcripts and raw audio recordings. Since we
manually corrected the transcripts to ensure accuracy, the SA
set is semi-automatic. To ensure a fair comparison between the
feature sets, all features were extracted at the exchange level.
The feature extraction and preprocessing steps are described in
more detail below.
2.2.1. System-dependent Features
The SD features were cleaned to address misaligned and missing
data. We applied per-dialogue forward fill to temporal features
and replaced missing values in categorical and string variables
with a null category or an empty string. The categorical variables
were then one-hot-encoded, and string variables—namely system
prompt and user utterance data—were encoded using one of
three pre-trained self-supervised models. Specifically, we
used RoBERTa2 [12], SBERT3 [13], and TOD-BERT4 [14] to
compare the efficacy of general-purpose, sentence-level, and
dialogue-specialised embeddings, respectively. Notably, the
system prompt and user utterance data were encoded as separate
inputs, resulting in two distinct embedding vectors for each
exchange.

2.2.2. System-agnostic Features
The SA features were derived using a multi-stage pipeline
designed to extract time-aligned transcripts from the dyadic
and user-amplified recordings in the LEGO corpus. First, voice
activity detection (V AD) was performed on the user-amplified
recordings using a pre-trained Silero model [ 15]. Second,
loudness normalisation and Gaussian noise injection were used
to mask residual system speech, followed by a second V AD
pass to isolate user speech. These speech segments were
then transcribed using a pre-trained Whisper large-v3-turbo
model [16], with WhisperX utilised for word-level alignment
[17]. After the user transcript and timings were manually
corrected, system speech segments were isolated by transcribing
the dyadic recordings and using string matching to align
the mixed transcript with the user transcript and the system
prompts (from the SD set). Finally, the system transcripts
were manually corrected and combined with the user transcripts.
To ensure reproducibility, the protocol used for manual
correction is included in the supplemental materials (see
correction protocol.pdf).
Acoustic features were extracted directly from the raw audio
recordings, using the timing information to isolate individual
exchanges. The OpenSMILE toolkit was used to extract 88
prosody and voice quality features from the eGeMAPSv02
feature set [ 18, 19]. To further capture high-level acoustic
representations, we compared the efficacy of three widely
adopted self-supervised models: HuBERT 5 [20], WavLM 6
[21], Wav2Vec 2.0 7 [22]. Since these models produce
frame-level embeddings, mean pooling was applied to generate
exchange-level features.
Linguistic features were derived from the time-aligned
transcripts. Text embeddings were generated using the
pre-trained models described in section 2.2.1. Additionally,
turn-taking features, such as turn duration, response latency, and
speech overlap, were calculated from the exchange-level timing
information. Finally, we identified user utterances containing
response tokens (e.g. “yes”, “oh” and “right”), which we used as
indicators of user attention, active listening, and backchanneling
behaviour [23, 24].
2.3. Experimental Pipeline
Model training and evaluation were conducted over two phases.
In Phase 1, feature extraction and classification functioned as
independent stages, with the pre-trained encoder weights frozen
to establish a baseline for each feature set. In Phase 2, we
developed an end-to-end architecture where the encoder, feature
fusion, and back-end components were jointly fine-tuned for IQ
classification. Both phases utilised an LSTM back-end, with
hyperparameter tuning to optimise the training regimes. These
experiments were conducted on a high-performance computing
cluster utilising NVIDIA A100 GPUs (80GB VRAM).
2.3.1. Phase 1: Static Feature Pipeline
Classifiers were trained using 10-fold grouped cross-validation
to optimise the pre-trained encoders (see Section 2.2), back-end
hyperparameters, and dimensionality reduction (the search space
is detailed in Table 1). Principal Component Analysis (PCA) was

2.3.2. Phase 2: Fine-Tuned Pipeline
The optimal configurations from Phase 1 were used to construct
the end-to-end pipeline in Phase 2. For the SA set, the front-end
consisted of one acoustic and one text encoder, whereas the SD
set utilised two independent text encoders to process the system
prompt and user utterance data. Each encoder’s output was
passed through a learnable projection layer for dimensionality
reduction. The projection outputs were then concatenated and
processed by a LayerNorm layer to balance feature contributions,
before being fed into the LSTM classifier.
Since fine-tuning is memory-intensive, adjustments were
necessary to the back-end parameters: batch size was set to
1 with gradient accumulation over 8 steps, and the classifier
was configured to use a sliding window to incorporate dialogue
context. These models were trained with an Adam optimiser and
early stopping (max epochs = 40, patience = 5), with the window
size, number of frozen encoder layers, and encoder learning rates
tuned (see Table 1). Notably, since SBERT is shallower than
RoBERTa and TOD-BERT (6 vs. 12 layers), the frozen encoder
layer search space was truncated (0, 3, 6) when SBERT was used
in the fine-tuned pipeline. Cross-validation was not performed
in this phase due to the computational demands of fine-tuning.
2.3.3. Evaluation Protocol
The best-performing models from Phase 1 and Phase 2 were
retrained on the full training set and evaluated on the test set. We
report Macro-F1 and unweighted average recall (UAR) scores
to address class imbalance and ensure comparability with the
existing literature. To address the instability of fine-tuning
large-scale encoders [26], the Phase 2 results are reported for
the median of five random seeds. In contrast, the results for the
Phase 1 models are reported as single-point estimates, given the
high stability of classifiers trained on static features.
Model performance is benchmarked against a majority
baseline and Ultes [ 6]. Unlike earlier studies [ 4, 5], both this
study and Ultes [6] utilise dialogue-wise partitioning to avoid
data leakage. Nevertheless, direct performance comparisons
require caution, as we employed a larger subset of the LEGO
corpus and the original train/test split was unavailable.
3. Results
3.1. Hyperparameter Tuning
The hyperparameter tuning results are detailed in Table 2. Across
both experimental phases, the system-dependent (SD) feature set
consistently outperformed the system-agnostic (SA) set, yielding
higher mean and maximum Macro-F1 scores. Shifting to a
fine-tuned architecture improved classification performance for
both feature sets, with the SD model achieving the highest overall
performance during tuning (MF1Max = 0.621).
As shown in Table 1, the optimal model architecture for
both feature sets was a unidirectional LSTM with self-attention.
Bidirectionality provided no additional benefit, suggesting that
future context was not critical for IQ classification. While the
optimal number of layers, head learning rate, and batch size were
consistent, the SA set required a larger hidden size and a higher
explained variance ratio for the text embeddings. Similarly,
while the SD set favoured SBERT, the SA set performed best
with a RoBERTa text encoder and WavLM acoustic encoder.
In Phase 2, both models benefited from freezing the bottom
three encoder layers, providing support for the use of selective
fine-tuning for IQ classification. The optimal window size
was larger for the SD set (15 exchanges), indicating that the
SD approach benefited from increased contextual information,
whereas the SA approach required a narrower focus. Finally, the
higher transformer learning rate for the best SA model suggests
that this approach required more aggressive updates to align the
multimodal features with the classification pipeline.
3.2. Model Evaluation
The model evaluation results are outlined in Table 3. All
trained models performed substantially better than a majority
baseline, with the SD set outperforming the SA set across
all metrics and pipelines. Furthermore, fine-tuning provided
a substantial performance boost over the static pipeline for
the SA set, suggesting that end-to-end adaptation allowed the
models to better utilise the SA features for IQ classification.
In contrast, fine-tuning resulted in a negligible difference in
performance for the SD set. Notably, our fine-tuned SD
model underperformed (UAR= 0.471 ) relative to the 0.540
baseline reported by Ultes [ 6]. This gap may stem from
differences in feature dimensionality: Ultes selected five system
log parameters, whereas our SD model used the full system
logs and self-supervised representations (D>100 ) to maintain
architectural consistency with our SA models.
To determine whether the performance differences between
the SA and SD sets were statistically significant, we conducted
six permutation tests [27], using a Holm-Bonferroni correction.
This analysis revealed that the static SA model performed
significantly worse than the static SD (p=.046 ) and fine-tuned
SA models ( p=.037 ). All other comparisons, including
those between the fine-tuned SA model and the SD models,
were non-significant (p > .05). This suggests that a static
IQ classification pipeline performs significantly better when
trained on SD features rather than SA features. However, when
end-to-end fine-tuning is employed, the SA approach achieves
comparable performance to the SD approach.
3.3. Computational Complexity
The computational efficiency of the best-performing models
is compared in terms of scale and latency. The static feature
models are relatively lightweight, with the SD and SA models
containing 1.05M and 2.29M trainable parameters, respectively.
The average inference latencies for these models were 0.10 ms
and 0.16 ms per exchange. In Phase 2, joint fine-tuning increased
the trainable parameter count to 12.18M for the SD set and
135.73M for the SA set. This resulted in increased inference
latencies of 6.02 ms (SD) and 17.98 ms (SA) per exchange.
Despite the higher complexity of the fine-tuned SA pipeline, all
models maintained inference latencies below 20 ms, making
them viable for real-time IQ monitoring.

4. Discussion and Conclusion
This study contributes to ongoing efforts to automate the
evaluation of spoken dialogue systems by comparing interaction
quality (IQ) classifiers trained on system-dependent (SD)
and system-agnostic (SA) features. The results demonstrate
that SA features are a viable alternative to SD features,
achieving comparable performance when end-to-end fine-tuning
is employed. However, when feature extraction and classification
are independent stages in a static feature pipeline, the SD features
offer superior classification performance.
This performance gap may stem from the fact that the SD
features are human-engineered summaries of the interaction,
which serve as direct proxies for dialogue breakdown. In
contrast, the SA set relied on high-level acoustic and textual
embeddings that contain extraneous linguistic and paralinguistic
information. In the case of the LEGO corpus, environmental
noise and poor speaker intelligibility could have obscured the
acoustic embeddings, resulting in inaccurate IQ predictions.
Fine-tuning appears to be critical here, enabling the pre-trained
encoders to ignore irrelevant noise and extract task-specific
features. However, this improvement in performance comes with
a substantial computational cost, as evidenced by the increase in
trainable parameter counts and inference latency. Consequently,

Future work could build upon these findings in several
ways. Firstly, since the LEGO corpus is a valuable but
dated benchmark, future research should focus on developing
contemporary datasets with IQ annotations to investigate the
generalisability of our findings. Secondly, while this study
relied on manually verified transcriptions to extract the SA
features, future work should develop fully automated SA
pipelines capable of classifying IQ from raw audio without
any human intervention, as this would allow for real-time,
scalable deployment. Finally, the LEGO corpus contains manual
annotations for user emotional state and dialogue acts, which
could be used in future work for multi-task learning. As
evidenced by Gupta et al. [ 7], training models to perform
multiple related tasks, such as emotion and dialogue act
prediction, may enhance IQ classification performance.
