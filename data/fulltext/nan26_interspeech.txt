Abstract
Existing speech annotation tools do not adequately support
model-assisted manual annotation workflows that use general-
purpose models to pre-annotate domain-specific speech data
followed by human refinement. As a result, the annotation
process remains time-consuming, inefficient, and difficult to
scale. We therefore present SpeechBench, an integrated tool de-
signed to facilitate this workflow. The tool incorporates trained
models for a range of speech processing tasks and provides
a graphical interface for constructing multi-step, model-based
pre-annotation pipelines, lowering the barrier for non-technical
users. It also supports flexible deployment on private servers to
meet strict data privacy requirements.
Index Terms: speech annotation, speech analysis, model-
assisted pre-annotation, human refinement
1. Introduction
With the rapid advancement of general-purpose speech mod-
els, such as Whisper for automatic speech recognition (ASR),
workflows that leverage these models to pre-annotate domain-
specific speech data (e.g., children’s speech)—for example by
generating time-aligned orthographic transcriptions—followed
by human refinement, have been shown to substantially im-
prove annotation efficiency, reducing both time and cost [1].
This paradigm reflects a broader shift toward human-in-the-
loop AI systems, where automated models and human expertise
are combined to improve both efficiency and annotation quality.
However, there is currently no speech annotation and analysis
tool that fully and effectively supports this workflow.
In practice, most existing tools do not fully integrate or ef-
fectively leverage modern speech models to enhance annotation
efficiency. Specifically, these tools are either primarily designed
for linguistic experts to analyze and annotate individual audio
files (e.g., Praat) [2], or they focus on annotator management
and task allocation for large-scale dataset processing (e.g., La-
bel Studio) [3], offering little to no model-assisted capabilities.
Although some libraries exist to facilitate model-assisted work-
flows [4], they typically require programming expertise, which
can be a barrier for non-technical researchers.
Transforming raw speech into a fully annotated dataset gen-
erally requires a sequence of interdependent processing steps,
e.g., voice activity detection (V AD) followed by speaker di-
arization and then ASR [1]. However, existing tools typically
support only a single task or a narrow class of tasks [3, 5]. With-
out pipeline-level support to chain and execute these tasks se-
quentially, each step must be performed independently, with in-
termediate outputs manually transferred and coordinated. As a
result, this task-centric design fundamentally limits the efficient
implementation of model-assisted annotation workflows.
Many existing tools are web-based and hosted on public
servers [3, 5]. This deployment paradigm often requires upload-
ing datasets to third-party infrastructure, raising serious data se-
curity and privacy concerns, particularly for those working with
sensitive speech data.
To address these limitations, we propose SpeechBench, a
unified tool for speech annotation and analysis. It integrates
key features, including a range of model-based speech pro-
cessing functionalities, a graphical interface that enables even
non-technical users to construct model-assisted pre-annotation
pipelines, and tier-editing capabilities to support human refine-
ment, all within a single environment. It also offers flexible de-
ployment options to ensure data privacy. Overall, SpeechBench
facilitates the practical adoption of model-assisted speech anno-
tation workflows. More broadly, it embodies a human-in-the-
loop paradigm, where general-purpose models provide scalable
pre-annotation and domain experts refine the outputs, aligning
with emerging trends in interactive and assistive AI systems.
2. System Architecture
SpeechBench follows a modular frontend–backend architecture
designed to decouple user interaction from computationally in-
tensive speech processing, enabling scalable pipeline execution
and flexible deployment across local and server environments.
Both components are containerized as Docker images, ensur-
ing reproducibility and simplifying deployment, particularly in
offline or privacy-sensitive settings.
The frontend is web-based and runs directly in a browser
without requiring additional client-side installation. It manages
user interaction and visualization, and is implemented using the
Vue 3 framework [6]. Audio playback, waveform and spec-
trogram visualization, and tier-editing functionalities are sup-
ported via the WaveSurfer.js library [7], providing an interactive
environment for annotation and analysis.
The backend is implemented in Python and is responsi-
ble for coordinating speech processing, model execution, and
data management. It processes analysis requests from the fron-
tend (e.g., pitch estimation) and integrates functionality built
on the Parselmouth library [8], enabling capabilities compara-
ble to Praat. In addition, the backend incorporates a range of
pretrained models supporting tasks such as V AD, speaker di-
arization, ASR, phoneme recognition, and forced alignment.
SpeechBench supports model-assisted annotation through a
pipeline execution framework, where processing tasks are mod-
ular components that can be composed into directed pipelines.
Outputs from each step (e.g., V AD segments) are passed as
structured inputs to subsequent steps (e.g., speaker diarization).

3. Demo Description
A laptop will be set up to demonstrate SpeechBench. It will run
without an internet connection to highlight its ability to oper-
ate locally while ensuring data privacy. Pre-recorded conversa-
tional speech will be used to showcase the annotation and anal-
ysis workflow. The full model-assisted annotation workflow of
SpeechBench will be demonstrated during the Show & Tell ses-
sion. As illustrated in Fig. 1 (a), this workflow consists of three
main stages: user and project management, model-assisted pre-
annotation pipeline definition, and human refinement, with each
supported by a dedicated user interface.
3.1. User and Project Management.To support con-
trolled access and user-specific data management, SpeechBench
provides a login interface, where users can sign in with an exist-
ing account or register a new one. After successful authentica-
tion, users are directed to the projects interface, where they can
create new projects or open existing ones. This design supports
scalable dataset management and enables users to organize an-
notation workflows across multiple projects and datasets. Once
a project is created or opened, the system moves to a project
overview interface, where users can manage the project’s audio
files, and key information about the files and overall annotation
progress is displayed.
3.2. Visual Pre-Annotation Pipeline Definition.Once an
audio file is selected from the project overview interface, users
can initiate the model-assisted pre-annotation process by adding
annotation tiers, after which they are directed to a dedicated
interface for defining the annotation pipeline, as illustrated in
Fig. 1 (b). This interface provides a set of functional modules
(shown in the left panel), each representing a speech process-
ing task required in a pre-annotation pipeline and supported by
trained backend models.
The key feature of this interface is the visual canvas, which
allows users to drag and arrange speech processing modules
to easily build and configure pre-annotation pipelines. By ab-
stracting complex model pipelines into visual components, this
interface enables non-technical users to construct sophisticated
multi-step workflows without programming expertise. Once ex-
ecuted, the resulting pre-annotations are displayed as annotation
tiers aligned with the waveform and spectrogram in the annota-
tion and analysis workspace, as shown in Fig. 1 (c).
3.3. Interactive Tier Editing for Human Refinement.
Human refinement is performed within the annotation and anal-
ysis workspace. This stage is essential for correcting errors
introduced by automated models and ensuring high-quality,
domain-specific annotations. Users can create, delete, and edit
regions within each tier, including modifying the content (e.g.,
revising ASR transcriptions) and adjusting start and end bound-
aries. Additionally, the workspace integrates core speech anal-
ysis functionalities (e.g., pitch estimation, formant estimation,
and vowel triangle) in the left panel, while the resulting visu-
alizations (e.g., vowel triangle plots) are displayed in the right
panel. Audio playback is also supported, allowing users to lis-
ten to selected regions for more precise refinement. This tight
integration of annotation and analysis reduces context switching
between tools and enables users to make informed refinement
decisions based on acoustic evidence.
4. Use of Generative AI Disclosure
Generative AI tools were used only for editing and polishing the
language of this manuscript. They were not used to write any
major part of the paper.
