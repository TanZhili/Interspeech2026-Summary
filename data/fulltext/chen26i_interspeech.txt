Abstract
Polyphone disambiguation is a crucial component for Chinese
Text-to-Speech systems. While recent arts achieve high ac-
curacy using large pre-trained models like BERT, their mas-
sive parameter sizes hinder on-device deployment. Further-
more, these closed-set classifiers fail to predict pronunciations
unseen during training. To address this, we propose g2pO, a
lightweight open-vocabulary framework. It adopts a tiny BERT
encoder and fuses external dictionary knowledge into hidden
states via a lexicon adapter. Instead of using heavy pre-trained
word embeddings to encode dictionary information, our method
dynamically constructs word representations from hidden states
via mix-pooling. These designs minimize the parameter size
and enable generalization to unseen pronunciations. Exper-
iments show with only 3.99M parameters (27x smaller than
BERT-based methods), g2pO outperforms previous methods,
achieving 99.15% accuracy on the CPP dataset and 70.79%
zero-shot accuracy on unseen pronunciations.
Index Terms: grapheme to phoneme, polyphone disambigua-
tion, lexicon information, lightweight, open-vocabulary
1. Introduction
Mandarin Grapheme-to-Phoneme (G2P) converts Chinese char-
acters into corresponding pronunciations (called pinyin), serv-
ing as a crucial component for text-to-speech (TTS) systems.
Even advanced Large Language Model (LLM) based TTS
models [1, 2] often mispronounce uncommon polyphones [3].
Therefore, employing an efficient and effective G2P module to
pre-process the input text for TTS systems remains highly nec-
essary in real-world deployments.
The primary challenge in Mandarin G2P is polyphone dis-
ambiguation (PD). A polyphone has multiple valid pronuncia-
tions, and the correct one is inferred from context. Early rule-
based [4, 5] and statistical [6, 7] methods demand extensive hu-
man effort for rules and feature engineering. Deep learning ap-
proaches instead learn from large-scale data. For example, bidi-
rectional Long Short-Term Memory (BiLSTM) is adopted to
encode contextual text features for PD [8, 9]. Auxiliary linguis-
tic features such as part-of-speech (POS) tags [8, 10] and word
segmentation [11] are also commonly used to improve PD.
Recently, Pre-trained Language Models (PLM) like
BERT [12] have been widely adopted to extract contextual
features for PD and achieved state-of-the-art (SOTA) perfor-
mance [13,14]. Since the pronunciations of Chinese polyphones
are largely determined by word context, explicitly incorporating
lexicon features further improves model performance. For ex-
ample, PDF [15] employs a flat-lattice structure to encode all

three major drawbacks that hinder practical on-device deploy-
ment. First, as a front-end module, the G2P model is expected

G2P models [8, 13–16] typically have more than 100M pa-

inherently fail to predict pronunciations unseen during training.

2. Proposed method
We treat PD as a classification task on the polyphonic charac-
ter. The overall architecture of g2pO is shown in Figure 1. It
consists of four modules: PLM encoder, lexicon fusion module
(Sec 2.1), POS prediction module (Sec 2.2), and phoneme pre-
diction module (Sec 2.3). The input is first encoded by the PLM
into contextual hidden states. Then the POS module predicts the
POS tag of the polyphonic character and converts it into a POS
embedding. Meanwhile, the lexicon fusion module fuses these
hidden states with lexicon features to produce enhanced char-
acter representation and lexicon prior. The POS embedding and
enhanced hidden state are then concatenated and fed to an MLP
to generate initial phoneme logits. Finally, a weighted softmax,
conditioned on the lexicon prior and a valid pinyin mask, shapes
these logits into the final phoneme probabilities. We elaborate
on each module in the following sections.
2.1. Lexicon fusion module
Inspired by LEBERT [19], we adopt a modified lexicon adapter
to fuse both word and pronunciation features into PLM’s hidden
states to improve PD performance. Our lexicon fusion module
is shown in Figure 2. It takes PLM’s hidden states and fea-
tures from the pronunciation dictionary as input to produce the
lexicon-enhanced hidden state and the lexicon prior.
2.1.1. Pair polyphone with dictionary words
We collect a Chinese dictionary (see details in Sec 3.2), where
each entry maps a Chinese word to its pinyin transcription (e.g.,
长江-chang2,jiang1). Similar to [19], we first construct
a Trie from the dictionary to enable efficient lookups. Then,
for a given input sentence and target polyphonic character, we
enumerate all substrings of the sentence containing the target
character and check them against the Trie. For any substring
that matches a word in the Trie, we form a pair consisting of this
word and the pinyin of the target polyphonic character within it.
These pairs are then used to form word representations.
2.1.2. Dynamic word representation construction
We propose a dynamic word representation construction mech-
anism based on PLM hidden states. Specifically, for each
matched word-pinyin pair, we first locate the word span[s,e]
within the input sentence. We then extract the correspond-
ing PLM hidden states{hs,hs+1,...,h e}and aggregate them
into a single word representationew via mix-pooling:

2.2. POS prediction module
In Chinese, the pronunciation of polyphonic characters is highly
correlated with their syntactic roles within a sentence. Moti-
vated by this linguistic observation, we introduce an auxiliary
POS prediction module. The POS predictor is an MLP with
one hidden layer, which takes the hidden representation of the
polyphonic character as input and predicts its POS tag. During
training, we employ a teacher-forcing strategy: instead of using

predictor but outputs logits over the pinyin vocabulary space.

During training, the PLM encoder is fine-tuned jointly with all
proposed modules. The model is optimized using two cross-
entropy objectives: the auxiliary POS prediction lossL pos and
the phoneme prediction lossL ph. Specifically,L pos is calcu-
lated between the predicted and ground-truth POS tags, and

the ground-truth pinyin labels. The overall objective is their

3. Experiments
3.1. Datasets
We evaluate g2pO on three public datasets: Chinese Polyphone
with Pinyin (CPP) [9], revised CPP (RCPP) [14], and Modern
Common Polyphone (MCP) [16]. Table 1 summarizes their key
statistics. RCPP refines CPP by fixing incorrect labels and filter-
ing out sentences targeting non-polyphonic characters. We fur-
ther use a small subset of the RCPP test set, denoted RCPP(S),
which removes biased test cases such as polyphones that appear
with only one pronunciation.
3.2. Implementation details
Dictionary Construction.We construct our pronunciation dic-
tionary by aggregating three public sources: the Modern Chi-
nese Dictionary (7th Edition) [22] 1, CC-CEDICT2, and Zdict3,
which initially provide 21,791, 109,696, and 29,335 word-to-
pinyin mappings, respectively. Each mapping contains at least
one polyphonic character in the word. By filtering out words

Model Configuration.We adoptRoBERTa-tiny 4 (2
hidden layers, 128 hidden size) as the PLM encoder. The last-
layer hidden states of the encoder are fed into the lexicon fusion
module. The MLPs in both the POS and phoneme predictors
have a hidden size of 256, using PReLU [23] activation and a
dropout [24] rate of 0.1. For weighted softmax, the temperature
τis set to 1 for seen polyphones and 10 for unseen ones.
Training Strategy.For the auxiliary POS prediction task,
we useJieba 5 to generate POS labels and treat them as ground-
truth during training. To reduce task complexity, we collapse
Jieba’s original 54 POS tags into 10 broad categories: adjec-
tive (A), conjunction (C), adverb (D), DE (DE), interjection (I),
noun (N), preposition (P), particle (T), verb (V), and unknown
(UNK). We setβto 0.1 to balance the POS loss in joint train-
ing. During inference, the model relies on its self-predicted
POS tags. To optimize our model, we apply label smoothing
with a factor of 0.1. Notably, rather than uniformly distributing
the smoothing weight across the entire output space, we restrict
it to the valid pinyin candidates of the target character, which
empirically yields higher accuracy on the evaluation set.
Optimization and Setup.The network is optimized by
AdamW [25]. The learning rate warms up from1×10−7 for the
first 4,000 steps and is subsequently set to5×10 −5. We train
the model with batch size 256 for 40,000 steps on one NVIDIA
A100 GPU. A fixed random seed is applied to ensure repro-
ducibility. For testing, we report the results using the check-
point that achieves the highest accuracy on the validation set.
Compared models.We evaluate our model together with
four representative Mandarin G2P methods:
•g2pM[9]: Building contextual representation of the poly-
phonic character using the BiLSTM or BERT model.
•g2pL[16]: Integrating pre-trained word embeddings [26]
into the bottom layers of BERT using a lexicon adapter to
aid pronunciation prediction.
•PDF[15]: Using a flat-lattice structure to allow the PLM to
encode both the characters and all potential words simultane-
ously to avoid segmentation errors.
•g2pW[13]: Constructing character and POS features to
guide the weighted softmax to condition the BERT output.
The evaluation metric is the pinyin prediction accuracy on
polyphonic characters. When reporting, results are quoted di-
rectly from the original papers whenever possible. Otherwise,
we train and test the models using their open-source code,
strictly following the instructions in their papers; methods lack-
ing public code are excluded in some experiments.

3.3.2. Ablation study
To verify the effectiveness of key designs in the g2pO model, we
conduct an ablation study on the CPP dataset. The results are
presented in Table 4. Removing the lexicon adapter yields the
largest drop (from 99.15% to 98.55%), confirming that word-
level dictionary knowledge is a useful auxiliary signal. No-
tably, this 98.55% corresponds to the setting where the exter-
nal dictionary signal is entirely removed. It indicates that g2pO
has internal disambiguation ability. We further verify this on
dictionary coverage: 35.1% of the polyphones in the CPP test
set are matched by no dictionary word, and on this uncovered
set g2pO still achieves 98.50%. This suggests that dictionary
knowledge benefits g2pO, but our model does not fully rely on
it. Removing the POS module also leads to a decrease in accu-
racy (98.91%), indicating that syntactic information is a valu-
able feature. Finally, discarding the lexicon prior slightly de-
grades performance to 99.10%, demonstrating that conditioning
the final weighted softmax with the lexicon prior further refines
the output probabilities.

3.3.3. Open-vocabulary generalization test
We derive a subset from the full MCP dataset for the open-
vocabulary evaluation. This subset contains 541 samples whose
target characters appear in the CPP training set, but whose
ground-truth pinyin labels are never paired with those charac-
ters during training. All models are trained on the CPP training
set and tested on this 541-sample zero-shot set. As shown in
Table 5, existing closed-set methods (g2pM, g2pL, and g2pW)
score 0.00% on this set because they cannot predict labels
outside their output space. In contrast, our method achieves
70.79% accuracy, as its design extends the output space be-
yond the character-pinyin pairs observed during training. The
matched words supply candidate pinyins, and the lexicon prior
selects the contextually correct one.

4. Conclusion
In this paper, we proposed g2pO, a lightweight and open-
vocabulary framework for Mandarin polyphone disambigua-
tion. By dynamically constructing word representations from
hidden states and explicitly conditioning predictions with a lex-
icon prior, g2pO minimizes storage cost and enables predic-
tion on unseen pronunciations. With only 3.99 M parameters,
it achieves state-of-the-art accuracy on public benchmarks and
strong zero-shot generalization to unseen pronunciations. Our
work provides a practical solution for low-resource, on-device
TTS applications.
