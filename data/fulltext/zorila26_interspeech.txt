Abstract
Embedding-based tool retrieval is challenging and often
fails in real deployments because API descriptors are incon-
sistent to what the embedding models are originally trained
with and often require fine-tuning or retraining from scratch.
The challenge is further amplified in speech driven queries,
where background noise can degrade automatic speech recog-
nition (ASR) outputs. We present a training free offline method
that leverages an LLM to generate diverse, user-style synthetic
queries, tasks, and scenarios for each tool, and then average (or
steer) the embeddings to form a semantically enriched tool rep-
resentation. To evaluate the robustness, we simulate realistic
speech conditions—including reverberation and additive noise
prior to ASR— and present experiments using multiple embed-
ding models and tool datasets. Our results show that the pro-
posed method provides a simple yet effective way to enhance
tool retrieval reliability without requiring any model retraining.
Index Terms: information retrieval, speech-to-API, large lan-
guage models, embedding steering
1. Introduction
Modern software ecosystems increasingly rely on large collec-
tions of modular tools, libraries, and APIs that users and agents
can invoke through natural-language interfaces and function-
calling abstractions [1, 2]. As these ecosystems grow, retriev-
ing the correct tool for a given user query becomes a critical
component of conversational assistants and automated reason-
ing systems. This challenge has been extensively highlighted
by recent tool-use systems and benchmarks that evaluate API
retrieval and argument correctness [3, 4, 5].
A common approach is to map both the user’s query and
the tool descriptions into a shared embedding space and se-
lect the most similar tool representation; however, prior work
shows that this seemingly simple retrieval step is often the pri-
mary bottleneck limiting end-to-end system accuracy due to
overlapping/ambiguous documentation and changing tool ver-
sions [4, 5]. Document and query expansion methods have been
proposed in information retrieval, where generating likely user
queries for documents [6] or synthesizing training queries [7]
were shown to improve retrieval without altering the underly-
ing retriever architecture. However, these approaches were de-
veloped primarily for static text corpora and do not directly ad-
dress several challenges that arise in tool-retrieval settings, such
as handling overlapping or ambiguous tool descriptions, com-
plex argument schemas, or the need to reason over functional
behavior.

A central challenge arises from the fact that API descriptors
are rarely standardized; their structure, style, and level of detail
vary widely across tools, as documented in natural-language-to-
API datasets like Okapi that target realistic web APIs and com-
positional generalization [8]. Many descriptors are noisy, am-
biguous, or incomplete and thus poorly aligned with the textual
patterns on which embedding models are typically trained. At
the same time, user queries (particularly in speech-based inter-
faces) may contain transcription errors introduced by automatic
speech recognition (ASR), further exacerbating the mismatch
between input queries and available tool descriptions [9, 10].
When both sides of the retrieval problem are noisy, even state-
of-the-art embedding models struggle to maintain robustness,
leading to degraded tool selection accuracy [3, 4, 5].
To address this issue, we propose a simple yet effective of-
fline embedding-steering strategy that uses large language mod-
els (LLMs) to enhance the semantic quality of tool representa-
tions. Instead of relying directly on the raw API descriptors,
the LLM is prompted to generate a diverse set of plausible use-
case scenarios, tasks, subtasks, and user-style queries associated
with each tool. By averaging the embeddings of these synthetic
steering queries, we obtain a more reliable and semantically en-
riched representation of each tool - one that better reflects how
users are likely to reference or interact with the tool in prac-
tice. This approach leverages query-generation techniques to
enhance tool representations, mitigating ambiguity and improv-
ing tool-selection accuracy in large-scale tool ecosystems.
We further evaluate the robustness of this approach under
realistic speech-based query conditions by simulating reverber-
ation and noise through controllable audio augmentation which
is known to cause ASR performance degradation [11, 12]. This
allows us to systematically analyze retrieval performance when
the ASR output is affected by environmental distortions. Our
experiments demonstrate that embedding steering consistently

2.2. Data generation
To generate speech data from existing text-to-API datasets, we
employed WhisperSpeech TTS [14]. WhisperSpeech is open-
source and it achieves high-quality multilingual speech synthe-
sis by reversing the Whisper’s ASR pipeline. To simulate re-
alistic acoustic conditions for the test data, we combined the
synthesized speech with simulated noise in two stages. Firstly,
a reverberated version of the clean synthesized signal is cre-
ated, then speech-shaped noise at different signal-to-noise ratios
(SNR) is added. To evaluate the impact of the acoustic noise on
the retrieval performance, Whisper ASR [15] is used to tran-
scribe the noisy data.
The full data generation pipeline is shown in Figure 3. In
our experiments we used the s2a-q4-hq-fast-en+pl Whisper-
Speech TTS model 2 and the Whisper base ASR model 3, both
with default configurations. In Figure 3, q0, qc and qn repre-
sent the reference query, the query transcribed from the clean
TTS signal, and the query transcribed from the noisy speech,
respectively.

istic choice for ASR evaluation. SSN is generated by passing
white noise through a 12-order linear predictive filter estimated
from a long speech signal. Finally, the noise is mixed with the

3. Evaluation
3.1. Data
We selected three widely used text-to-API datasets to build
our speech-to-API benchmark, covering both single-API and
multi-API query scenarios. Gorilla [5] provides large-scale
instruction–response pairs and focuses on resolving ambigui-
ties arising from APIs with overlapping functionalities; in this
work, we use the Gorilla-HF subset, which includes about
925 Hugging Face models across 37 domains, each solvable
with a single API call. Ultratool [16] contains annotated,
real-world task scenarios with natural-language instructions,
tool lists, environment states, and execution traces; we use
only its natural-language instructions from the test set. Finally,
ToolACE [17] offers a much larger collection of over 26,000
APIs across more than 3,000 fine-grained domains, support-
ing evaluations of complex API-driven tasks. In our experi-
ments, we adopt the standardized format from [20] for all three
datasets. The parallel speech-to-API corpus is constructed fol-
lowing the procedure explained in 2.2, and a summary descrip-
tion of this corpus is presented in Table 1, along with the av-
erage WERs for both clean and noisy speech. The complexity
of each task is also indicated, defined as the average number of
APIs needed to resolve a query within that task.
3.2. Embedding models
We evaluated four text-embedding models. The first is the
bert-base-uncased model, a transformer-based encoder
pretrained on a large English corpus using a self-supervised
learning objective [21]. This architecture consists of 12 en-
coder layers with 12 self-attention heads and a hidden size of
768, totaling roughly 110 million trainable parameters. Al-
though widely used as a backbone for fine-tuning in various
downstream tasks, it has not been adapted for API selection.
The second model, Tool-Retriever [4], is a fine-tuned
variant of BERT optimized specifically for API retrieval. It is
trained on more than 16,000 real-world APIs paired with user
queries, enabling the model to map both queries and relevant
APIs into a shared high-dimensional embedding space. The
last two embedding models are bge-base-en-v1.5 and
bge-large-en-v1.5 that produces 768-dimensional vec-
tor representations for semantic search and dense retrieval [22],
which have 109 and 335 million parameters, respectively.
This model selection strategy combines baseline,
domain-specialized, and state-of-the-art retrieval models
to evaluate how architectural differences, scaling effects,
and task-specific training influence speech-to-API retrieval
performance. BERT-base provides a neutral baseline, the Tool
Retriever captures tool-specific semantics, and the BGE models
are high performance general purpose models. Cosine simi-
larity was employed during evaluation to maintain consistency
across embedding models.
3.3. Evaluation metric
The evaluation is performed using the Normalized Discounted
Cumulative Gain (NDCG) [23], a standard metric in informa-
tion retrieval. NDCG quantifies how effectively a system ranks
the most relevant items near the top of a results list, assign-
ing lower weight to correct results that appear further down the
ranking. This property makes it particularly suitable for eval-
uating retrieval performance on complex queries. The score is
normalized by the ideal ranking and ranges from 0 to 1, where
1 represents a perfect ordering. For readability, all NDCG val-
ues in this work are multiplied by 100 and are denoted as N@x,
where x represents the length of the result list.

A second ablation examines how the steering weight α in-
fluences retrieval performance across different embedding mod-
els (Figure 4). All models exhibit a consistent trend: moder-
ate steering values (α∈ [0.25, 0.5]) yield the highest NDCG,
while very small or very large weights reduce effectiveness. No-
tably, the larger BGE model achieves the strongest overall gains,
peaking nearα = 0.5, suggesting that balanced steering (rather
than full replacement or no steering) best captures useful com-
plementary information from the LLM-generated queries. This
demonstrates that the embedding-steering mechanism is most
effective when it acts as a controlled refinement of the original
embedding space.
6. Conclusions
This paper presented an embedding-steering strategy to im-
prove speech-to-API retrieval when both tool descriptors and
ASR-generated queries are noisy or poorly aligned. By prompt-
ing an LLM to generate diverse, semantically meaningful steer-
ing queries for each tool, we produced enriched embeddings
that better capture user intent. Our experiments showed consis-
tent retrieval gains across embedding models and datasets, in-
cluding in challenging reverberant and noisy speech conditions.
The method is simple, training-free, and easily integrated into
existing pipelines, offering a practical way to enhance retrieval
robustness in real-world speech interfaces.
