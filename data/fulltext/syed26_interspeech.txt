Abstract
We presentcorpusgen, an open-source Python toolkit for de-
signing speech corpora with maximal phoneme coverage across
languages. The toolkit integrates grapheme-to-phoneme con-
version via espeak-ng, phoneme inventories from PHOIBLE
(covering 2,186 languages), and multiple corpus optimization
algorithms including greedy set cover with CELF acceleration,
integer linear programming, distribution-aware selection, and
NSGA-II multi-objective optimization. Beyond selection from
existing text,corpusgensupports targeted sentence genera-
tion through pluggable backends including LLM APIs and local
transformer models with phonotactic control. A unified eval-
uation module reports phoneme, diphone, and triphone cov-
erage alongside distribution quality metrics. The toolkit is
pip-installable, provides both a Python API and a CLI, and
is released under the Apache-2.0 license. We demonstrate its
application to corpus design across typologically diverse lan-
guages, showing how coverage-optimized selection achieves
near-optimal phoneme coverage with significantly fewer sen-
tences than random baselines.

cover optimization, text-to-speech, low-resource languages
1. Introduction
Phonetically balanced speech corpora are essential for training
text-to-speech (TTS) and automatic speech recognition (ASR)
systems, yet designing such corpora remains a largely ad-hoc
process. For well-resourced languages, established tools like
FestV ox [1] provide greedy selection pipelines, but these are
typically limited to specific languages and scripts. For the
majority of the world’s languages—particularly low-resource
ones—practitioners must build custom pipelines from scratch,
often resulting in corpora with significant phonetic coverage
gaps.
The corpus design problem is well-studied: selecting a min-
imum set of sentences that covers all phonetic units of a lan-
guage maps directly to the NP-hard Set Cover Problem [2].
Greedy algorithms achieve a(lnn+ 1)-approximation [3], and
submodularity of phoneme coverage functions enables further
acceleration via lazy evaluation (CELF) [4]. Multi-objective
formulations balancing coverage, naturalness, and recording
cost have been addressed with NSGA-II [5]. Despite this
mature algorithmic landscape, no unified, language-agnostic
toolkit exists that integrates evaluation, selection, and genera-
tion in a single framework.
We presentcorpusgen, an open-source Python package
that addresses this gap. The toolkit provides: (1) comprehen-

2. System Overview
Figure 1 shows the architecture ofcorpusgen. The system
is organized around three user-facing commands—evaluate,
select, andgenerate—that share a common infrastructure
layer for G2P conversion, phoneme inventory management, and
coverage tracking.
2.1. Infrastructure Layer
The G2P pipeline wraps espeak-ng [7] via the Phonem-
izer library, providing IPA transcriptions for 100+ languages.
A mapping bridge aligns espeak-ng’s output symbols to
PHOIBLE’s [6] canonical IPA inventories, handling macrolan-
guage resolution (e.g.,ms→Standard Malay) and system-
atic symbol normalization. PanPhon [8] provides articula-
tory feature vectors for phoneme distance computations. The
CoverageTrackermaintains running counts of phoneme,
diphone, and triphone occurrences, enablingO(1)marginal
gain lookups during selection.
2.2. Evaluate
Given a text corpus and a target language, the evaluation module
produces a structured report including: (a) phoneme, diphone,
and triphone coverage percentages against the PHOIBLE inven-
tory; (b) distribution quality metrics—Jensen-Shannon diver-
gence, Shannon entropy, and a composite Phoneme Coverage

2.3. Select
The selection module implements six algorithms.Greedy set
coverprovides the standard(lnn+ 1)-approximation baseline.
CELF[4] exploits submodularity for up to two orders of mag-
nitude speedup via lazy marginal gain evaluation.Stochas-
tic greedysamples candidate subsets for linear-time scaling
to large pools.ILPformulates exact set cover via PuLP for
ground-truth comparison on small instances.Distribution-
awareselection augments coverage objectives with a KL-
divergence term matching corpus phoneme distributions to a
target.NSGA-II[5] provides Pareto-optimal solutions over
competing objectives such as coverage, corpus size, and nat-
uralness.
2.4. Generate
When no suitable text pool exists, the Phon-CTG
(Phonotactically-Controlled Text Generation) module
generates sentences targeting specific coverage gaps. A
GenerationLoopiterates over missing phonetic targets,
dispatching requests to one of three pluggable backends:
(a)Repository, which searches HuggingFace datasets for
sentences containing target phonemes; (b)LLM API, which
prompts cloud-hosted models via litellm with phonetic con-
straints; (c)Local, which runs quantized transformer models
with inference-time guidance. Generated candidates are scored
by a phonetic scorer and an n-gram phonotactic model before
acceptance.
3. Demonstration
The live demonstration walks attendees through a complete cor-
pus design workflow using thecorpusgenCLI.
Step 1: Inventory inspection.The user queries the
phoneme inventory for a target language (e.g., Bengali) via
corpusgen inventory --language bn. The tool
displays the PHOIBLE-sourced phoneme set, the espeak-ng
mapping, and any unmapped symbols, giving the user a clear
picture of the phonetic targets before corpus construction be-
gins.
Step 2: Baseline evaluation.Given an existing text corpus,
corpusgen evaluateproduces a coverage report identi-
fying which phonemes, diphones, and triphones are present,
which are missing, and how the observed distribution compares
to a uniform or reference distribution. The coverage satura-
tion trajectory reveals whether adding more text from the same
source would yield diminishing returns.
Step 3: Optimized selection.Starting from the same text
pool, the user runscorpusgen selectwith different algo-
rithms (greedy, CELF, distribution-aware). The demonstration
compares the number of sentences required to reach 95% and
100% phoneme coverage across algorithms, and shows CELF
achieving equivalent coverage to greedy in a fraction of the
wall-clock time.
Step 4: Gap-filling generation.For any remaining cov-
erage gaps, the user invokescorpusgen generateto pro-
duce targeted sentences via the LLM API backend. The demon-
stration shows the generation loop iterating over missing di-
phones, producing candidate sentences, and scoring them for
phonetic content and phonotactic well-formedness.
The demonstration repeats this workflow across two to
three typologically diverse languages (e.g., English, Bengali,
Arabic) to illustrate language-agnostic operation. The accom-
panying video submission shows the full workflow and presents
a summary comparison of algorithm performance.
4. Conclusion and Availability
corpusgenprovides a unified, language-agnostic toolkit for
phoneme-coverage-optimized corpus design, integrating eval-
uation, selection, and generation in a single pip-installable
package. The toolkit is open-source under the Apache-2.0 li-
cense and available on PyPI (pip install corpusgen)
and GitHub.1 A persistent DOI is archived via Zenodo [9]. The
framework has been validated across 40 languages spanning 12
language families, and we invite the speech community to ex-
tend it to additional languages and use cases.
